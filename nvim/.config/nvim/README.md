# Шпаргалка по Neovim

`<leader>` — пробел. Сначала найди нужный код, затем внеси изменение, проверь diff и добавь в Git только нужные части.

На стартовом экране нажми `r`, чтобы открыть эту шпаргалку в режиме только для чтения. Тема — Moonfly с прозрачным фоном. HEX-коды `#RGB`, `#RGBA`, `#RRGGBB` и `#RRGGBBAA` подсвечиваются своим цветом. Русская раскладка работает в Normal mode через `langmap`; `spelllang` настроен для английского и русского языков (проверка включается командой `:set spell`).

## Поиск и навигация

| Клавиши | Действие |
| --- | --- |
| `<leader>ff` / `<leader>fb` | Найти файл / открытый буфер |
| `<leader>fg` / `<leader>fl` | Поиск текста в проекте / нечёткий поиск в текущем файле через Telescope |
| `<leader>fu` | Найти первое совпадение с начала файла до `#` в строке |
| `/`, `n`, `N` | Поиск в файле и переход между совпадениями |
| `gd`, `gr`, `<C-o>` | Определение, использования символа, возврат назад |
| `<leader>e` | Открыть файловый менеджер Oil |
| `<C-h>` / `<C-j>` / `<C-k>` / `<C-l>` | Переход между окнами и панелями tmux, в том числе из Oil |
| `<leader>oh` / `<leader>or` в Oil | Открыть файл в горизонтальном окне / обновить список |
| `<C-p>` в Oil | Включить или выключить предпросмотр; выбор сохраняется до завершения Neovim, при запуске предпросмотр включён |

В Telescope `<C-q>` переносит результаты в quickfix; `]q` / `[q` листают их. `<leader>fu` считает `#` началом комментария в любой строке и не разбирает синтаксис языка.

## Рефакторинг и проверка

`gr` — найти использования, `<leader>rn` — переименовать символ через LSP, `<leader>ca` — доступные действия. `<leader>fd` показывает диагностику, `[d` / `]d` переходят между ошибками. Сохранить файл — `<leader>w`; форматировать вручную — `<leader>cf`.

## Git и Gitsigns

| Клавиши | Действие |
| --- | --- |
| `<leader>gs` | Git status в Telescope |
| `<leader>gc` / `<leader>gC` | Коммиты проекта / текущего файла |
| `<leader>gb` / `<leader>gS` | Ветки / stash |
| `<leader>g]` / `<leader>g[` | Следующий / предыдущий изменённый блок |
| `<leader>ghp` | Показать изменение в текущем блоке |
| `<leader>ghs` | Добавить блок в Git index; в Visual mode — выделенную часть |
| `<leader>gdu` / `<leader>gds` | Список unstaged / staged файлов слева и единый diff справа |
| `<leader>gdU` / `<leader>gdS` | Двухоконный Diffview для unstaged / staged изменений |
| `<leader>gdc` / `<leader>gdf` | Закрыть просмотр / перейти к списку файлов |
| `<leader>gdt` / `<leader>gdx` | В Diffview: показать список файлов / сменить расположение окон |
| `<leader>ghs` / `<leader>gsa` / `<leader>gua` в панели Diffview | Добавить или убрать выбранный файл из index / добавить все / убрать все |
| `<leader>gr` / `<leader>gcl` в панели Diffview | Восстановить выбранный файл / открыть журнал коммитов |
| `<leader>gdh` | История текущего файла |

Чтобы пройтись по изменениям проекта, нажми `<leader>gdu` для unstaged или `<leader>gds` для staged: слева останется список файлов, справа откроется единый diff с добавленными и удалёнными строками. В списке `j` / `k` выбирают файл, `<CR>` переводит фокус к diff. `]q` / `[q` или `<Tab>` / `<S-Tab>` переключают файлы из любого окна; `<leader>g]` / `<leader>g[` переходят между блоками diff. `q` или `<leader>gdc` закрывают просмотр. Новые файлы, ещё не добавленные в Git, в список unstaged не входят.

Для сравнения старой и новой версий рядом используй `<leader>gdU` для unstaged или `<leader>gdS` для staged. В панели Diffview `j` / `k` и `<CR>` выбирают файл, `<Tab>` / `<S-Tab>` переключают файлы прямо в diff. Закрыть Diffview — `<leader>gdc`.

Для проверки одного файла: `<leader>g]` → `<leader>ghp` → при необходимости `<leader>ghs`.

## Конфликты при мердже

`<leader>gdU` открывает просмотр конфликта, `<leader>gxl` собирает конфликты в quickfix. В конфликтном файле `<leader>gxn` / `<leader>gxp` листают конфликты; `<leader>gxo` / `<leader>gxt` / `<leader>gxb` выбирают ours / theirs / both, `<leader>gx0` удаляет обе стороны. В Diffview `<leader>gxv` выбирает base. Перед выбором посмотри обе стороны: при rebase смысл ours и theirs легко перепутать.

При наличии маркера `<<<<<<< ` автоформатирование при сохранении пропускается. `<leader>cF` переключает автоформатирование для текущего буфера, если нужно сохранить уже разрешённый файл без дополнительных изменений.
